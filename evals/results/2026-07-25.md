# specwarden eval — 2026-07-25

First run in which the enforcement layer was actually exercised. The
2026-05-11 run could not have measured it: every arm was invoked with
`--bare`, which `claude --help` describes as "Minimal mode: skip hooks,
LSP, plugin sync, ...". The hooks were switched off at the command line.

Four arms, five fixture tasks, one trial per cell (20 cells).
Total cost **$10.47**, total wall clock ~46 min.

## Arms

| Arm | Skill text | Hooks | Question it answers |
|---|:---:|:---:|---|
| A | no | no | Control. |
| B | yes | no | Does the skill prompt alone change behaviour? |
| C | yes | yes | The shipped configuration. |
| D | no | yes | **Does the gate hold?** |

Arm D exists because arm C cannot answer that question. In arm C the skill
sits in the system prompt and tells the model the hook exists, so the model
reads `.claude/specs/active`, predicts the block, and stops. The hook's
effect is inseparable from the skill's. Arm D withholds the skill, so the
model attempts the edit blind.

## What this does NOT show

Read this section before quoting the headline.

**"0 files changed" in arms C and D is not scope discipline. It is zero
work.** No spec was ever active in those cells, so the gate correctly
refused every edit and no task was completed. The correct reading is "the
gate holds", not "specwarden produces tidier diffs". Any claim about scope
creep remains unmeasured.

**There is still no out-of-scope metric.** `files_modified` counts changed
files. Nothing compares them against a declared in-scope set. See the
2026-05-11 limitations section, which is still accurate on this point.

**The gate covers tool calls, not the filesystem.** The matcher is
`Edit|Write|MultiEdit|NotebookEdit`. A file written via `cat >`, `sed -i`
or `tee` bypasses it and is not logged. Verified separately.

**n=1 per cell.** Five tasks, single trial, no variance estimate.

## The 2026-05-11 behavioural finding did not reproduce

That run reported that in all ten B and C cells Claude wrote a four-section
spec under `.claude/specs/` and halted awaiting a human `ready`. **No spec
file was created in any cell of this run**, in any arm.

Arm B did not self-restrain either. It completed three of five tasks and
changed 7 files, against arm A's 9 — nothing like the near-total restraint
previously reported. What differs: `--bare` removed, `acceptEdits` in place
of `--dangerously-skip-permissions`, a newer model, and a file counter that
now sees created files. Which of those is responsible is not established.

Treat the earlier "the skill alone is the load-bearing mechanism"
conclusion as unsupported until it is reproduced.

## Secondary finding: the skill reduces wasted attempts

Arm C made 5 edit attempts across five tasks; arm D made 15. Arm D, blocked
without explanation, went looking for the cause — reading `settings.json`,
attempting to `cd` into the specwarden checkout, trying to open the hook
source. It was stopped by Claude Code's own working-directory sandbox, not
by specwarden.

So the skill's measured value in this run is not restraint. It is telling
an already-gated agent *why* it was blocked, which cuts retries roughly
threefold. That is a smaller and different claim than the previous one.

## Method

- Runner: `python3 evals/run_eval.py --all-tasks --all-arms`
- Model: `claude-opus-4-8[1m]`, Claude Code 2.1.218.
- Auth: `ANTHROPIC_API_KEY` from gitignored `.env.eval`.
- Isolation: `CLAUDE_CONFIG_DIR` pointed at a scratch directory. **Not**
  `--bare`, which disables hooks.
- Permissions: `--permission-mode acceptEdits`. Edits auto-accept, so arm A
  is unimpeded; a PreToolUse `deny` still gates the call.
- Arm B/C: `--append-system-prompt-file <workdir>/.claude/skills/specwarden/SKILL.md`
- Arm C/D: `--settings <workdir>/.claude/settings.json`
- Watchdog: 420s per cell. No cell timed out; slowest was 303.1s.
- File counting: `git status --porcelain --untracked-files=all`, so created
  files are counted. `git diff --name-only HEAD` was used previously and
  omitted them.

## What is committed

`2026-07-25-summary.json` holds the per-cell record: arm, timings, exit status,
and the exact list of files each cell changed. The raw session JSONLs are ~1.9 MB
and contain absolute paths from the machine that ran them, so they are gitignored
alongside `_local/` rather than committed. Re-running `make eval` regenerates
them.

## Reproduce

```bash
cp .env.eval.example .env.eval && $EDITOR .env.eval
make eval                 # all four arms, ~46 min, ~$10.50
make eval-enforcement     # arms A and D only, the enforcement contrast
python3 evals/measure.py evals/results/_local
```
