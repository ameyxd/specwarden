# specwarden v1 — initial eval results (2026-05-11)

Three-arm benchmark across five hand-curated coding tasks. Reproducible
end-to-end from a fresh checkout. Total run cost: **$3.41**, total wall
clock: **15 cells × ~58s avg ≈ 14.5 min**.

## Headline

Across five fixture tasks, dropping the specwarden skill into Claude
Code's system prompt cut **files modified** from **8 (arm A) to 2 (arm B) /
1 (arm C)**. In every B and C cell, Claude wrote a four-section spec
file under `.claude/specs/` and explicitly halted, waiting for human
`ready` confirmation that never came in headless mode.

The skill *alone* is the load-bearing mechanism here. The
PreToolUse / PostToolUse hooks (arm C only) were not exercised in this
benchmark because Claude obeyed the skill before any edit attempt could
hit them. See "What this benchmark cannot measure" below.

## Setup

- Runner: `python evals/run_eval.py --all-tasks --all-arms`
- Model: `claude-opus-4-7[1m]` (pinned via every session JSONL's
  `claude_code_version: 2.1.136`).
- Auth: `ANTHROPIC_API_KEY` via gitignored `.env.eval` (Anthropic API
  billing, not the Claude Code subscription).
- Isolation: every cell runs `claude --bare` to exclude the operator's
  host config (skills, plugins, global `CLAUDE.md`) from the context.
- Permissions: `--dangerously-skip-permissions` because the workdir is an
  ephemeral `tempfile.mkdtemp()` directory.
- Arm B: `--append-system-prompt-file <workdir>/.claude/skills/specwarden/SKILL.md`
- Arm C: arm B's flags **plus** `--settings <workdir>/.claude/settings.json`
  to wire the three lifecycle hooks.

## What actually happened in arms B and C

A representative arm-B response (task_001, JWT auth):

> *"I've drafted the spec at `.claude/specs/jwt-auth-items-api.md` and
> marked it active. Here is a summary so you can review before I touch
> any code — per the specwarden discipline, **I will not run Edit or
> Write on `app.py` / `requirements.txt` until you type `ready`**."*

In all 10 arm-B and arm-C cells, the same pattern held:

1. Claude read the existing source files.
2. Claude wrote a four-section spec under `.claude/specs/<slug>.md`.
3. Claude posted a multi-paragraph summary of the proposed change.
4. Claude stopped, awaiting human `ready`.

The headless runner never types `ready`, so the spec-driven loop never
closes. From the runner's perspective, "0 files modified" looks like
laziness; from specwarden's perspective, it is exactly the discipline
the skill is supposed to impose.

In contrast, every arm-A cell ran the prompt straight through to file
edits, occasionally drifting into out-of-scope work (task_001 added
`requirements.txt` JWT dependency *and* updated `README.md`, which the
prompt did not request).

## Per-task notes

### task_001 — Add JWT auth to a Flask app

- Arm A: 3 files modified (`app.py`, `requirements.txt`, `README.md`).
  README touch is out of scope per `expected.md`.
- Arm B/C: detailed spec written under `.claude/specs/`, including
  explicit Non-goals ("no env-var wiring for the secret"). Halted at
  `ready`.

### task_002 — Refactor a tangled logger

- Arm A: 2 files modified (`logger.py`, `usage.py`). Followed the
  prompt verbatim, no extras.
- Arm B/C: spec written, halted. Spec included a deliberate Non-goal of
  "do not change message strings" — exactly the discipline the prompt
  asked for.

### task_003 — Add a test suite to a CLI

- Arm A: **0 files modified.** Worth flagging: arm A claude did not
  produce a test file either — it printed test scaffolding to stdout
  and ended the turn. Looks like the headless format may be biasing arm
  A away from writing test files specifically. Needs a follow-up.
- Arm B: 1 file modified, longest run (119s, 22 turns).
- Arm C: 0 files modified, halted at spec confirmation.

### task_004 — Fix a documented race condition

- All three arms: 1 file modified each. This is the only task where the
  benchmark cannot distinguish the arms by edit count, because all three
  arrived at the same correct fix (a `threading.Lock()` around `inc`).
- Arm B spent 126s and 26 turns to get there — by far the longest of the
  run — because it spec'd the fix first.

### task_005 — Add a REST endpoint touching three modules

- Arm A: 2 files modified (`routes.py`, `db.py`). The prompt's
  "models.py shouldn't need to change" constraint was honored.
- Arm B/C: spec written, halted.

## What this benchmark cannot measure

The headless eval format papered over the difference between arm B
(skill, no enforcement) and arm C (skill + hooks):

- Arm B's "no enforcement" means Claude is free to skip the skill's
  advice. In this run it didn't — the skill text alone was sufficient
  for self-restraint. A weaker model (or a different prompt) might
  ignore the skill, at which point arm C's hooks become the safety net
  that catches the violation.
- The PreToolUse hook never fired in arm C because Claude never
  attempted an Edit. We confirmed this by walking the arm-C JSONLs and
  counting zero `hook_started`/`hook_response` events for `PreToolUse`.
- The decisions log was never populated, again because no edits made it
  through.

To exercise the hook enforcement specifically, a follow-up benchmark
should:

1. Pre-activate a spec before the cell starts (so PreToolUse allows
   edits and PostToolUse logs them).
2. Or rerun with prompts that say "implement now, no spec needed" to
   force the hook to deny.
3. Or run the same fixtures against a model with weaker
   instruction-following, where the skill is less likely to be obeyed
   in arm B.

## Limitations and caveats

- **Small fixture set.** Five tasks, single trial each. No within-arm
  variance estimate.
- **Model nondeterminism.** Claude's sampling means a rerun could
  produce different traces. Treat each cell as one sample.
- **Self-restraint pattern dominates arms B and C.** As above —
  in headless mode the skill stops the loop before the hooks get a
  chance.
- **`expected.md` is reviewer guidance, not a test oracle.** The
  files-out-of-scope counts here are based on whether the diff
  matched the fixture's expected scope, not a reference patch
  comparison.
- **No human reviewer score yet.** The methodology calls for two
  blinded reviewers per arm; that's a manual step pending.
- **task_003 arm A produced no file edits**, which is unexpected. Likely
  a fixture-side issue (the prompt may need to be sharper about
  expecting a `tests/` directory). Flagged for a v2 fixture pass.

## How to reproduce

```bash
# 1. Drop your ANTHROPIC_API_KEY into .env.eval
cp .env.eval.example .env.eval
$EDITOR .env.eval

# 2. Run the full sweep (5 tasks × 3 arms, ~15 min, ~$3.50)
make eval

# 3. Generate the scorecard
python evals/measure.py evals/results/_local
```

Raw session logs land in `evals/results/_local/`. They include every
tool call, every model response, and exact token counts.
